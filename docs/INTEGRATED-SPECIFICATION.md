# World Prediction Engine 統合企画・要求仕様書

文書版：1.0 ／ 作成日：2026年10月7日（日本時間）

本書は、これまでの会話で提示された目的・思想・要求を、開発と検証に使える形に統合した設計成果物である。発言の逐語録ではない。会話に登場した未検証の一般化や原因の断定は、確認済みの事実ではなく検証課題として整理する。本書の作成は、コードの更新・GitHubへの公開・常時稼働の開始を意味しない。

## 1. プロジェクトの目的

WPEは、公開情報を継続的に収集し、状況の変化、関係者の利益と制約、社会制度の働きを分析して、将来起こり得る出来事と事前の備えを提示する研究・開発プロジェクトである。

最優先の目的は、被害が起きる前に危険の兆候を捉え、心構え、回避、準備を支援すること。世界情勢を対象とする独立した個人プロジェクトとして育て、生成AIの品質管理に関するキャリアプロジェクトとは別軸で扱う。

哲学的な動機は、予測と備えによって不意打ちを減らし、他人を無理に変えることに依存せず、仕組みや自分の行動を通じて平穏に暮らすことである。ただし、被害や予測の失敗をすべて本人の責任とする設計にはしない。予測不能な出来事は残り、加害や制度不全の責任は予測の成否と別に扱う。

### 成果として提供するもの

- 出典付きの状況整理と、情報の更新履歴。
- 根拠と不確実性を示した期限付きの予測。
- 重大だが確率を算出できない危機シナリオ。
- 関係者ごとの利益・負担・影響力・準備行動の可視化。
- 警戒する兆候、判断の見直し条件、現実的な備え。
- 予測結果の事後評価と、モデルの改善履歴。

## 2. 思想を設計へ変換する

| 会話での方針 | システムの仕様 |
|---|---|
| 性悪説を基礎に備える | 善意を必要条件にせず、利益、機会、制約、監督の弱点を分析する。協力や抑止が働く場合も観測して残す。 |
| 人間を現実的に見る | 社会心理・行動に関する研究を仮説の根拠とする。個人の内心を断定せず、状況と観測行動を扱う。 |
| 起きてからでは遅い | 先行指標、他地域の先例、制度変更、保護体制の不足を早期警戒に使う。 |
| 低確率の重大被害にも備える | 確率が低いことだけで除外せず、重大さと対策負担を合わせて優先順位を付ける。 |
| 相手を変えるより仕組みで対応する | 回避、監督、相談経路、証拠保全、環境改善など、利用者が選べる対応を提示する。 |
| 利権と受益者を可視化する | 受益、負担、影響行使、事前準備を分離し、各リンクに根拠を付ける。 |

「あらゆる出来事は特定の人物が企てた」「全員が悪意を持つ」といった前提は置かない。受益者がいることと、受益者が出来事を引き起こしたことは別である。

## 3. 三つの出力を分ける

### 3.1 観測事実

何が、いつ、どこで報告・記録されたか。発生日時、公開日時、取得日時を分離する。報道上の容疑、被害申告、裁判所の認定、集計統計を異なる状態として保存する。

### 3.2 発生予測

対象、地域、期限、結果の判定条件を先に定義する。数値確率を出す場合は、その算出方法、学習・評価期間、比較対象、予測の幅を示す。データが足りなければ「確率算出不能」とする。LLMが文章から作った数字を、統計的に検証された確率として表示しない。

### 3.3 危機シナリオ

確率が分からなくても、重大な被害につながる具体的な経路があれば記録する。必要条件、先例、警戒兆候、反証条件、対策を必須項目にする。シナリオの存在を「高確率」の意味で表示しない。単に想像できるだけの筋書きと、先例や観測に支えられた筋書きを区別する。

## 4. 利害関係と次の行動の分析

政策変更を初期の中心テーマとし、次の関係を追う。

> 政策・制度の変化 → 利益と負担の変化 → 関係者の行動候補 → 社会的影響 → 結果の検証

| 分析軸 | 記録する内容 | 断定しないこと |
|---|---|---|
| 受益・負担 | 収入、費用、権限、アクセス、リスクの変化 | 受益したから黒幕であるとはしない。 |
| 影響行使 | 提案、資金提供、働きかけ、決定参加、確認できる関係 | 関係があるだけで違法な共謀とはしない。 |
| 事前準備 | 発表、投資、契約、設備増強などの時系列 | 早い準備だけで内部情報の利用とはしない。 |
| 事後対応 | 出来事の後に始まった行動や利益 | 事後の適応を事前の企てと混同しない。 |

行動候補は「条件Aが成立し、制約Bが弱ければ、行動Cが利益になる」のように記述する。実行能力、代替行動、実行費用、規制、評判への影響も含める。「利益がある」は「必ず実行する」ではない。

## 5. 犯罪・被害リスクの範囲

基本の予測単位は「地域 × 期間 × 被害・犯罪種類」。児童婚、強制婚、性的被害、配偶者からの暴力、差別に伴う暴力、設備の盗難・破壊、組織犯罪などを候補にする。対象は順次増やし、最初から世界全域を同じ精度で扱うと約束しない。

### 5.1 宗教・文化・教育をどう扱うか

宗教的・文化的な規範が加害を容認し、被害者の相談や離脱を妨げる場合は分析に含める。実際の被害への備えは、その正当化の証拠がすべてそろうまで待たない。

ただし、宗教名、民族名、出身地域だけを使って、個人の犯罪性を判定する機能は作らない。集団内の違いと移住先の条件を失うと、危機回避に必要な具体性がなくなるためである。

| 関心領域 | 検証する具体的な観測項目 |
|---|---|
| 児童婚・強制婚 | 婚姻年齢、法律上の例外、実態調査、容認する発言、教育継続、保護へのアクセス。 |
| 女性への暴力 | 暴力を正当化する規範、離婚・避難の困難さ、相談への報復、事件と被害調査。 |
| カーストなどによる差別 | 交際・婚姻への制裁、社会的排除、脅迫・暴行の記録、司法へのアクセス。 |
| 教育状況 | 就学、中退、識字、教育機会、雇用との関係。低学歴を個人の犯罪性と同一視しない。 |
| 設備の盗難・破壊 | 過去の事件、転売市場、管理体制、組織の関与、損害・復旧記録。 |
| 移住に関連する変化 | 移住先の事件・被害率、年齢構成、生活・就業条件、制度と支援へのアクセス、犯罪組織の活動。 |

出身地の被害率を移住先へそのまま移植しない。国・地域・期間・定義をそろえ、人口当たりの率と件数を両方示す。宗教や民族による差の分析は、データが何を測っているかと他の条件の影響を併記する。

### 5.2 法律と被害を分離する

現地法が許容している行為でも、児童や女性への被害は分析対象となる。「現地法上の犯罪」「人権侵害・有害な慣行」「被害申告」を別項目にする。犯罪の法的定義が変わった場合、単純な前後比較をしない。

認知件数、容疑者登録、検挙、起訴、有罪、被害調査、通報率は相互に代用しない。通報増加や取り締まり強化で記録件数が増える可能性も評価する。

## 6. 警察・検察・司法の機能不全

「制度が必ず守ってくれる」という前提を置かない。被害後に救済が遅れ、再被害につながる可能性も危機シナリオに含める。

| 層 | 対象とする問題 | 根拠の例 |
|---|---|---|
| 初動・保護 | 届出不受理、対応遅延、避難や保護の不足 | 相談・申立て記録、監査、第三者調査。 |
| 捜査 | 証拠収集の不足、紛失、通訳・人員不足 | 判決理由、検証報告、懲戒・監査資料。 |
| 処分・裁判 | 不起訴理由、判決理由、不服申立ての結果 | 公開資料、検察審査、裁判記録。 |
| 腐敗・介入 | 贈収賄、利益相反、圧力、隠蔽、改ざん | 確認できる文書、資金・関係資料、調査結果。 |

不起訴は検察の処分、無罪は起訴後の裁判所の判断として分ける。処罰に至らなかった事実だけでは、加害の事実や腐敗の原因を確定しない。反対に、原因が不明でも保護の不足への備えは検討できる。

国籍別の処分差を調べる場合、同じ罪名・時期・処理区分をそろえる。事件の性質や証拠の違いを考慮せずに総数だけから優遇・腐敗を認定しない。公式統計も、第三者調査や別の資料と照合する。

## 7. データ収集と証拠管理

優先する情報源は、公的統計、法律・議会資料、裁判・監査資料、研究、組織の公式発表、信頼できる報道。SNS・動画は早期の手掛かりとして扱い、原出典、日時、場所、編集の有無を確認する。

各情報には次の項目を持たせる。

- URL、発行主体、資料名、原文の該当箇所。
- 発生日時、公開日時、取得日時、改訂日時、対象期間。
- 地域、定義、分母、単位、欠測、集計方法。
- 情報の状態：報告、申告、容疑、認定、仮説、訂正。
- 独立した裏付け、反対の資料、利用・保存条件。

取得失敗を「事件ゼロ」としない。記事の数を事件数にしない。同じ配信元の転載を独立した裏付けとして数えない。情報源の更新、削除、訂正を追えるよう原文の版と取得履歴を管理する。

## 8. 微分・積分の役割

数値化できる指標を時間系列として扱い、微分に相当する差分で変化の速さを、積分に相当する累積量で継続的な負担や異常を把握する。

\[
v_t = \frac{x_t-x_{t-1}}{t_t-t_{t-1}}, \qquad
A = \sum_t \frac{x_t+x_{t-1}}{2}(t_t-t_{t-1})
\]

間隔と単位を必ず表示する。報道量の累積は被害の累積ではない。欠測をゼロで埋めず、季節性、人口変化、統計定義の変更を扱う。差分はノイズを増幅するため、平滑化の方法と遅れも示す。

微分・積分だけで将来や因果関係が決まるわけではない。観測の変化を把握する特徴量として使い、過去の基準率、予測モデル、関係者の行動分析、シナリオと組み合わせる。

## 9. 警戒と対応の優先順位

次の四項目を分けて表示する。

1. 発生可能性：推定できる場合の確率、推定不能の場合の理由。
2. 被害の重大さ：身体、生活、財産、回復可能性への影響。
3. 兆候の強さ：証拠の質、独立性、新しさ、関連性。
4. 対策の負担：費用、時間、副作用、実行可能性。

これらを検証せず単一の危険点数へまとめない。低確率でも重大で、負担の小さい備えなら早めに提示する。大きな負担を伴う行動には、追加確認や見直し条件を示す。

通知には地域・期間・理由・取るべき行動・解除条件を付ける。新情報がないのに同じ警告を反復しない。個人や集団への嫌がらせ、自力での制裁を対策として出力しない。

## 10. システム構成と自律運用

収集、原文保存、出来事抽出、時系列指標、利害関係台帳、予測・シナリオ、対応案、結果評価を分離する。SQLiteなどの保存基盤から始め、実測した規模に応じて拡張する。

自動化する範囲は、公開情報の定期取得、重複排除、指標更新、候補抽出、既定ルールに基づくレポート更新。社会的に重大な人物への告発、因果の断定、未検証の外部公開は人による確認を設ける。

外部APIの制限、取得間隔、再試行、失敗ログ、費用上限、停止・再開を設定する。LLMを追加する場合は、文書中の命令を実行指示として扱わず、構造化出力の検証と引用照合を行う。収集した文書から勝手に外部操作を実行しない。

## 11. 共通レポートの書式

各案件は次の順序で出力する。

1. 予測対象、地域、期限、結果の判定条件。
2. 確認済みの事実と出典。
3. 受益者・負担者、影響行使と事前準備の根拠。
4. 基準となる予測、悪化・改善のシナリオ。
5. 警戒兆候、反証・解除条件、不足している情報。
6. 利用者が選べる備えと、その費用・限界。
7. 予測の作成時点、改訂履歴、事後の結果と評価。

データ不足の例：確率は「算出不能」、シナリオは「○○の条件が重なれば△△の被害が起こり得る」、行動は「条件を確認するまで負担の小さい準備を進める」と表示する。架空の確率を埋めない。

## 12. 開発段階と受け入れ基準

| 段階 | 成果物 | 完了を判断する条件 |
|---|---|---|
| A：基盤の照合 | 既存版の機能一覧と再現手順 | 既存コード・設定・テストを読み、本書の要求との差を記録する。 |
| B：政策分析 | 原文から利益・行動候補までの案件レポート | 引用を追跡でき、断定と仮説を区別し、期限付きの結果評価ができる。 |
| C：地域リスク | 一地域・一種類の被害を扱う予測 | 定義と分母が明確で、過去の時点で利用可能だったデータだけで評価する。 |
| D：制度不全 | 保護・捜査・処分の時系列台帳 | 不起訴と無罪、対応不全と腐敗の証拠を分けて検索できる。 |
| E：早期警戒 | 条件付きシナリオと通知 | 警戒理由、対策、解除条件を表示し、重複通知と取得失敗を適切に扱う。 |
| F：対象拡張 | 複数地域・複数テーマ | 地域差・定義差・費用・運用負荷を測定し、性能の限界を公開する。 |

予測は過去の平均や季節性などの単純な基準モデルと比較する。確率予測にはBrier scoreと校正、件数予測には誤差と予測区間の被覆率を使う。警戒には見逃し、誤警報、先行時間、対策負担を記録する。評価に必要な標本数と許容値は対象決定後に事前設定する。

少数の的中例だけで能力を主張しない。過去情報への未来データの混入、同じ事件の重複、報道の選択偏りを検査する。性能が改善しない機能は、用途を制限するかシナリオ扱いに戻す。

## 13. 既存成果物との関係

既存成果物として `world-prediction-engine-v0.3.zip` の存在を確認した。本書はそのZIPを改変せず、追加の統合要求を定義する独立文書である。

過去の会話では、時系列処理、情報取得、原文引用、利害関係台帳、条件付き行動予測、評価機能などが報告されている。ただし、本書作成時にはZIPのコードを再読・再実行していないため、それらを今回検証済みの実装として認定しない。犯罪・被害リスク、司法不全、早期警戒の本書仕様は、実装完了を意味しない。

次の実装作業は段階Aから始め、既存の機能を再利用できる範囲と追加が必要な範囲を確定する。

## 14. Git・GitHubとポートフォリオ

リポジトリは、目的・限界・起動手順を記したREADME、コード、テスト、設定例、設計文書、架空または再配布可能なサンプルを中心に構成する。収集した原文、個人情報、APIキー、ローカルDBは公開対象を個別に判断し、秘密情報をコミットしない。

Gitは履歴管理、GitHubは共有先である。ローカルで動作確認し、公開する内容を確認してから、リモートの作成とpushを行う。既存リポジトリの名称や公開設定は、本書だけでは変更しない。

ポートフォリオでは「世界の未来を正確に当てるAI」と主張せず、情報の来歴、予測の検証、失敗時の挙動、仮説の管理、再現性を示す。QAの経験は、未来データの混入検査、情報源障害への対応、判定条件の定義、誤警報の評価に活かせる。

## 16. 今回の合意を開発方針としてまとめる

WPEは、重大な被害に対して確定前から備えるための仕組みとする。利害関係、具体的な規範、教育・生活条件、犯罪の機会、警察・司法の不全を分析に含める。観測事実、原因の仮説、数値予測、危機シナリオを分け、反証と結果評価を残す。利用者が行動を選べる根拠を示し、備えの費用と限界も伝える。
