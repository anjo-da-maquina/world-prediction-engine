# v0.3設計・開発方針

## プロジェクトの目的

世界の変化を観測し、利害・能力・制約・相互作用から複数の未来を考え、配慮と備えの選択肢を増やす。
生成AIの品質管理のキャリア向けプロジェクトとは独立して開発する。
善意・自制が働かない局面をストレスシナリオに含める。一方、確率は観測データで検証し、最悪の展開を必然と表示しない。
人間・集団の行動は生存、資源、所属、地位、損失回避、制度的な制約等の仮説とデータから推定する。
協力・改善・制約による行動不能も候補に含める。

## 利害の二つの経路

働きかけ→中間変化→出来事→利益と、事前情報→予測→準備→出来事→利益を別々に扱う。
同一主体が両方に該当し得る。受益の存在だけで出来事への関与は確認できない。
受益者不明、偶発的な受益、発生後の対応、純損失の可能性を保持する。
確認する各経路に証拠と取得時刻を付け、途切れた経路を想像で埋めない。

## 実装したデータモデル

| テーブル | 内容 |
|---|---|
| document_texts | 本文の版、取得時刻、ハッシュ、元の取得ID |
| evidence_spans | 原文の引用範囲、正確な文字位置、入手時刻 |
| policy_events | 制度・政策への言及候補 |
| event_reviews | 候補に対する確認・否定・不明の追記履歴 |
| entities | 明示的に同定した主体と種類・地域 |
| interest_links | 出来事と主体の関係、分析軸、根拠、競合する説明 |
| action_forecasts | 行動問題、期限、情報基準時刻、実登録時刻、確率、方法、判定ルール |
| action_outcomes | 初回判定、根拠、理由、Brier |

v0.2のDBには新しいテーブルを追加し、既存観測・予測は維持する。
v0.2に本文テーブルはないため、新版で取得した資料から本文・候補を蓄積する。
候補抽出は辞書と文区切りであり、否定や引用の意味解釈をしていない。
法案の成立・施行を認定するには議案・公式発表等の追加確認が必要。会議録の一発言は成立の証明ではない。

## 自律化の範囲

自動: 定期取得、原文保存、言及候補、既に登録した利害からの定型行動候補、参考ベースレート、数値予測の評価。
明示的登録: 主体の同定、利害経路、事実の確認、行動の期限付き予測、行動結果の判定。
LLMを接続する際も上記の引用一致・時間検証へ通す。記事の命令を実行せず、JSONの項目を限定する。
LLM分析の正確さを人の評価と比較してから、自動処理の対象を増やす。

## 検証方針

引用一致と時点管理は必要条件であり、証拠の内容の真実性や因果を保証しない。
人物・団体の同定、抽出の正確さ、出来事の確認、行動予測を別々に採点する。
行動予測は現段階では手動推定または同じ行動ラベルのベースレート。校正済みではない。
同じ行動ラベルでも制度や企業・国が異なれば比較可能性が崩れるので、文脈別評価を追加する。
後から入力した過去予測は前向き実績に含めない。同じ問いの更新を独立問題として大量採点しない。
観測できなかった行動は未解決。確認できない内面・秘密活動を真実として出力しない。

## 次工程

1. 実通信と継続運転を確認し、取得遅れ・欠測・切り捨てを測定する。
2. 一つの制度変更に対して関係者と判定可能な行動問題を登録する。
3. 公式企業資料等を追加し、行動の確認経路を整える。
4. LLMによる根拠付き抽出を接続し、抽出精度を評価する。
5. 前向き予測を蓄積し、ベースラインと比較する。
6. 有効性を確認した領域を多国・多分野へ拡張する。

## 情報源

国会会議録API公式仕様: https://kokkai.ndl.go.jp/api.html
一度の発言検索は最大100件。収集は一情報源一サイクル一リクエスト。
利用条件に沿い、短時間の大量アクセスや並列アクセスはしない。
e-Gov法令API、企業IRの取得、国会議案の成立追跡はこの版では未接続。
