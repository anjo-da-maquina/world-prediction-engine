# 統合仕様との対応（v0.4）

仕様書全体を一度で実現した版ではありません。検証可能な基盤と、シナリオ・警戒の実装を提供します。

| 要求 | 状態 | 主な場所／限界 |
|---|---|---|
| 公開情報の定期収集 | 実装済み・模擬通信で検証 | autonomous.py、policy_source.py。実API・24時間運転は未検証。 |
| 原文・引用・情報基準時刻 | 実装済み | actors.py、risk.py。元情報の真実性は自動認定しない。 |
| 利害関係と行動候補 | 実装済み | actors.py。利害の登録は手動、候補は定型ルール。 |
| 微分・積分 | 実装済み | core.py、signals.py、regional.py。因果推論ではない。 |
| 期限付き数値予測・Brier | 実装済み | core.py、actors.py。校正された現実の精度は未実証。 |
| 地域×期間×指標の分析 | 部分実装 | 地域観測の保存・分母・定義・率・差分。犯罪専用の学習モデルは未実装。 |
| 危機シナリオと反証・備え | 実装済み | risk.py。数値確率は付与しない。 |
| 不起訴と無罪・腐敗の分離 | 実装済み | stage検証、根拠・別の説明を必須に。入力分類は登録者判断。 |
| 条件付き早期警戒 | 実装済み | 時点判定・欠測・鮮度・重複抑止・SQLite通知。外部配信なし。 |
| 期限後の結果判定 | 実装済み | 手動resolve。負の結果に網羅性宣言を要求。 |
| 通知の誤警報・見逃し・先行時間の集計 | 未実装 | ログと結果を残す基盤まで。評価集合と指標定義を先に決める。 |
| 世界の犯罪統計・司法記録の自動取り込み | 未実装 | 出典別の定義・利用条件・取得API・改訂履歴を設計して追加する。 |
| 宗教的・文化的規範の解析 | 登録による対応 | 条件・先例・根拠を記録。集団名や個人属性からの犯罪性採点は行わない。 |
| 自動利害分析・社会心理モデル | 未実装 | LLMや因果モデルを使う前に評価データと引用照合を設計する。 |
| 常時ホスト・通知サービス | 未配備 | loop/Dockerの雛形。費用上限の自動管理は未実装。 |
| GitHubへの公開 | 未実行 | ソース、CI、手順を同梱。 |

次の段階は一地域・一被害種類を選び、公式データの定義と履歴を確認したコネクタを追加すること。
モデル開発では未来データの混入、分母と報告率、記録・法的定義の変更を先に扱います。
