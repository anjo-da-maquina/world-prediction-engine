# 自律型世界予測AI — 到達目標と現在の実装

## 到達目標

観測範囲と取得品質を明示し、世界状態の推定、複数の未来分布、現実との照合、モデルの更新を継続する。
「完全に世界の全情報を収集した」「完全自律だから正しい」とは扱わない。

## 数理の役割

状態をX(t)、観測をY(t)、外部入力をU(t)とする。
観測モデル: Y(t)=h(X(t))+measurement_noise。
状態変化モデル: dX/dt=f_theta(X(t),U(t))+process_noise。
将来は現在状態と仮定した外部入力に対するこの変化モデルを積分し、確率的な軌道を生成する。
不確実性とモデル差を保ったままP(event | information_cutoff)を推定する。
単に観測値を微分し、その微分を積分しても概ね元の系列へ戻るだけで未知の未来は出ない。

| 演算 | 目的 | 例 | 制約 |
|---|---|---|---|
| 一次差分 | 変化速度 | 運賃の上昇速度 | 単位・間隔・季節性の管理 |
| 二次差分 | 加速度 | 上昇が速まったか | ノイズ増幅、後方フィルタ必須 |
| 基準超過積分 | 累積負荷 | 運賃の平常値超過×日 | 明示的な基準と欠測処理が必要 |
| 状態方程式の積分 | 将来の軌道 | 供給不足→価格→需要のシミュレーション | 変化モデルと外部入力の仮定が必要 |
| 確率評価 | 発生可能性 | 定義済み危機の期限内発生 | 校正・基準モデル比較・前向き検証 |

今回の版は表の最初の三つと、単純な統計的軌道サンプリングを実装。状態方程式の同定は未実装。

## LLMの追加方法

文書を読むLLMは、タイトルや原文の引用位置を付けて構造化出力する。
出来事の発生時刻・報道時刻・主体・場所・種類・数値・単位・否定・仮定表現・信頼度を区別。
出力をJSON schemaで検証し、根拠のない値を拒否する。
抽出誤りはQAで採点し、重複記事を一つの出来事へ統合する。
記事から与えられる指示はシステム指示として実行しない。
LLMが生成した因果関係は仮説として登録し、統計的識別の条件と反証材料を別に保持する。
LLMの文章上の自信を世界の出来事の確率とみなさない。
費用・対象文書数・トークン上限を定め、モデル名とプロンプト版を記録する。

## 多角的予測

安全保障、経済、金融、資源・食料、技術・雇用、気候・災害、日本への波及を別々に定義する。
問題の例は「GDP成長率が特定の定義で負になる」「観測油価が閾値を超える」等の判定可能なもの。
戦争や危機については規模、地域、発生条件、期限、判定元を具体化する。
シナリオは併発可能性を扱い、AI成長と紛争拡大を排他的な選択肢として扱わない。
危機と緩和を同時に仮説へ入れ、安定化の証拠も検索する。
モデルごとの得意領域、分散、相互相関、校正を検証してから重みを決める。
1,000本の軌道を10万本に増やしても、誤った仮定や入力は直らない。

## 自律的に改善する工程

候補特徴量・モデルを提案 → 過去時点情報だけで検証 → 独立した検証区間で比較 →
並行運転で既存モデルと前向き比較 → あらかじめ定めた条件を満たした場合のみ採用 →
劣化したら既存のモデルへ戻す。
予測台帳とモデル版を保持し、外れた予測を消さない。
新たな情報源は出典・単位・公開遅れ・利用条件・言語や地域の偏りを検証する。
無制限にデータ源やモデルを増やす自律性より、再現・評価できる変更を積み重ねる。

## 実行環境

このチャットを閉じた後も動くには、常時稼働するPCまたは外部ホストが必要。
コード: GitHub、実行: 独立プロセス、観測・予測: 永続DB、原文: DBまたはオブジェクトストレージ。
本格化時はPostgreSQLへ移行し、取得処理とモデル処理のジョブを分ける。
プロセス再起動、DBバックアップ、ディスク監視、API利用制限、費用上限、健康状態通知を設定する。
通知先やクラウド契約はこの版では設定していない。
GitHubにコードを保存することと、システムを常時運転することは別工程。
