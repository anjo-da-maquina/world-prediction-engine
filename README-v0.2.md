# World Prediction Engine v0.2 — 自律運転の土台

指定した情報源の取得 → 数値化 → 微分・積分 → 条件付き予測 → 台帳保存 → 判定を、独立したPythonプロセスで繰り返します。
Python 3.10以上、標準ライブラリのみ。v0.1のコード・テストを保持した追加版です。

**完成した万能AIではありません。LLM、因果推論、統合された世界モデル、自己学習によるモデル更新は未実装です。**
自動収集と統計モデルの運転基盤を実装しました。外部ホストへのデプロイ・実通信・24時間耐久運転は未検証。

## 1回実行

このREADMEのあるフォルダで:

```bash
python -m unittest discover -s tests -v
python -m wpe.autonomous once
```

ネット接続が必要。結果は`outputs/latest.json`と`outputs/runs/`に保存。
取得データ・文書・予測・判定は`data/runtime.sqlite`に保存。
`status: degraded`は情報源の取得失敗。`pending_data`は学習・判定用データ不足。
実データ不足を合成値や架空の確率で埋めません。

## 継続運転

```bash
python -m wpe.autonomous loop --tick-seconds 60
```

60秒ごとに処理時刻を確認し、情報源ごとの間隔で取得します。
RSSは1時間、World Bankは1日。PCを停止・スリープすると処理も止まります。
Ctrl+Cで終了。DBを保持すれば次の起動で取得済みデータと予測を引き継ぎます。
周期は実行時間に加算される方式で、厳密な壁時計の時刻保証はありません。
別の端末では新しいDBを用意するか、停止状態でDBを移してください。
同じDBを使う複数プロセスの同時サイクルをSQLiteのロックで防止します。

## 初期情報源

config/autonomous.jsonで指定:
- Federal Reserve: 公表資料RSS
- BIS: 研究資料RSS
- World Bank: 日本のインフレ率、米国と世界のGDP成長率

公式情報源のサンプル構成です。世界全体の網羅的収集ではありません。
RSSのタイトル・概要にキーワードがあるかを判定します。生成AIによる意味理解ではありません。
現在は公表文書の受信件数と話題の言及件数を測定し、実際の事件数や危機発生確率と混同しません。

## 日時・数値化

- RSSに書かれた公表時刻と、初めて取得した時刻を別々に保存。
- 一意キーによる同一フィード内の重複除去。複数提供元の同じ話題の統合は未実装。
- 生のRSS/API応答を取得日時・SHA256と一緒にDBへ保存。
- UTC日単位で、前日以前の受信件数を確定。
- 成功した取得がない日は欠測。成功があった日のゼロ件は「このシステムの新規受信がゼロ」であり、世界の事件がゼロという意味ではない。
- 初回取得日の件数には古い記事の初回取り込みを含む。RSSは過去の全記事を保証しない。
- 1回以上の取得成功を日次測定の最低条件にしている。運用では予定取得回数に対する網羅率の厳格化が必要。
- 今日の途中件数を確定観測値として予測へ入れない。
- World Bankの現行値は取得日がknown_on。当時の公表値が不明な過去年の値を、当時既知だった値にしない。
- 日内改訂が衝突した場合は収集失敗として記録。日内vintageを保持するtimestampスキーマへの拡張は未実装。

## 微分・積分・予測

微分はv0.1の後方平滑化と不等間隔差分。
積分は基準値を上回る部分の面積を計算:

`Integral = ∫ max(value(t) - baseline, 0) dt`

点間は線形補間。符号を跨ぐ区間は交点を計算して正の三角形の面積のみ積分。
単位は入力値の単位×日。許容間隔を超える欠測があれば積分を拒否します。
インフレ率の基準超過面積は「パーセントポイント×日」であり、物価水準や損失額ではありません。

予測は二系統:
1. ベースレート＋過去類似窓の固定平均。定義済みの閾値超過問題を予測台帳へ保存し、期限後にBrierを採点。
2. 過去の日次差分から独立に再標本化する数値軌道を1,000本生成。将来値の10/50/90分位を出力。

後者は未校正の比較用モデルで、時間依存・因果・レジームを無視します。
変数によって負の値等の非現実的な値も生成し得るため、実用モデルとして採用しないでください。
連続した30日以上の日次値と新鮮な観測が必要。年次指標の7日先投影は拒否。
分位点はrun履歴に保存しますが、自動採点は閾値超過問題のみ。

初期の予測問題は「FRBフィードの新規受信件数が、7日以内にある日20件を超えるか」というパイプライン検証用の問題です。
戦争・景気後退の予測は未実装。根拠なくこの件数をそれらの確率へ変換しません。

## 運用・拡張

- 取得: 25秒タイムアウト、通信失敗時は最大2試行、応答最大5MiB。
- 1情報源の失敗は他の情報源と分離。取得失敗中の情報源に依存する新規確率予測は停止。
- XMLのDTD/ENTITYは拒否。設定URLとリダイレクトはHTTPS。
- 設定や記事からコードを実行する機能、自己改変、無制限探索はない。
- 認証不要の情報源のみ。APIキー利用・LLM接続は次工程。
- 確定した日次値は上書きしない。期限後の負のRSS判定には全日の日次観測が必要。
- 原文を含むDB・run履歴は増え続ける。利用条件、保存期間、ディスク容量、バックアップを運用前に設定する。
- Dockerの常時運転設定は含むが、この環境ではDocker実行未検証。
- モデル性能評価・学習更新の完全自動化はまだ含まれない。

次の設計はdocs/AUTONOMOUS-DESIGN.md。前版の説明はREADME-v0.1.md。
GitHubへは解凍したコードをアップロードし、data/outputsを除外します。

## Dockerでの運転（設定のみ、実行未検証）

DockerとComposeが利用できる常時稼働環境なら:

```bash
docker compose up -d --build
docker compose logs -f wpe
docker compose stop
```

data/outputsをホストへ保存し、コンテナ再作成時にも残します。
ホストやDockerの停止・スリープ中は動きません。自動再起動にはDocker自体の起動設定も必要。
停止前に通信処理の終了を待つ場合があります。DBのコピーはプロセス停止後に行ってください。
Dockerfile/compose.yamlは生成した設定であり、この環境では実行していません。
